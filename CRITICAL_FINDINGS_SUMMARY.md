## 🔴 Task 2: Projects/Campaigns Fix - BLOCKED BY DATABASE MISMATCH

**What was requested**: Fix the campaign/projects feature that user reported as "still not working properly and is useless"

**What was discovered**:
### **CRITICAL BLOCKER: Environment/Database Mismatch**

**The Problem**:
- **Application codebase**: Built for PostgreSQL + Prisma ORM
  - `prisma/schema.prisma` line 8: `provider = "postgresql"`
  - `.env`: `DATABASE_URL="postgresql://rankseo:dev_password@localhost:5432/rankseo"`
  - All tRPC routers (`project.ts`, `auth.ts`, `opportunity.ts`, etc.) use Prisma client
  - Entire data layer expects PostgreSQL

- **Preview Environment**: Has only MongoDB
  - `supervisorctl status` shows: `mongodb RUNNING`, no PostgreSQL service
  - `.emergent/emergent.yml`: `env_image_name: "nextjs_mongo_shadcn_base_image_cloud_arm"`
  - `/etc/supervisor/conf.d/supervisord.conf` lines 15-20: Runs MongoDB only

**Impact**: 
- 🔴 Projects completely non-functional (cannot create, list, view)
- 🔴 Authentication broken (cannot login - no user database)
- 🔴 All features broken: opportunities, subscriptions, support tickets, invoices, etc.
- All database operations fail with: `Can't reach database server at localhost:5432`

**Testing Evidence**:
- Attempted authenticated screenshot test of projects page
- Login failed - redirected back to signin
- Console shows: `ClientFetchError: Failed to fetch` for `/api/auth/session`
- Backend logs show: Link verification job fails with Prisma connection error
- Manual check: `mongosh --eval "db.getMongo().getDBNames()"` returns only `['admin', 'config', 'local']` (empty)

**Why Backend Tests Passed Before**:
Previous testing agent likely mocked Prisma or tested in isolation without real database connection. The actual runtime environment has no PostgreSQL.

**Cannot Be Fixed with Code Changes**:
This requires infrastructure/platform change. Two options:
1. **Recommended**: Change preview environment to PostgreSQL (align env with codebase)
2. **Not Recommended**: Migrate entire codebase to MongoDB + Mongoose (weeks of work, complete data layer rewrite)

**Status**: 🔴 **BLOCKED** - Requires platform support to provision PostgreSQL database

## 🔴 Task 4: Mailgun Failure - EXTERNAL CONFIGURATION REQUIRED

**What was discovered**: 
Reviewing previous session logs and handoff summary confirms:

**Issue**: Mailgun returns `403 Forbidden` on all send attempts
**Root Cause**: Sending domain `rankdseo.com` is unverified in Mailgun
**Error From Logs**: "sending domain requires DNS verification"

**What This Means**:
- Mailgun is in sandbox mode
- Can only send to manually authorized recipients
- User must verify domain ownership via DNS records in Mailgun dashboard

**Affected Features**:
- Unpaid user campaign emails
- Password reset emails
- Email change verification
- Account deletion confirmation
- Support ticket notifications

**Cannot Be Fixed with Code**:
This requires user action in external Mailgun dashboard:
1. Login to Mailgun
2. Navigate to Sending → Domains
3. Add DNS TXT/CNAME records to domain registrar
4. Wait for verification (can take up to 48 hours)

**Status**: 🔴 **BLOCKED** - Requires user action in Mailgun dashboard. No code changes can fix this.
